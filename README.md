## 🏢 О проекте и назначение системы

При строительстве объектов капитального строительства в Москве возникает критический разрыв между:
1. **Проектной документацией (ПД)**, прошедшей государственную экспертизу (Мосгосэкспертиза);
2. **Рабочей документацией (РД)**, по которой генподрядчик непосредственно ведёт строительно-монтажные работы на площадке;
3. **Исполнительной документацией (ИД)** — актами освидетельствования скрытых работ (АОСР), исполнительными геодезическими схемами и паспортами материалов.

Несогласованные изменения (самовольное изменение марок бетона, уменьшение сечений арматуры, перенос несущих перегородок, изменение габаритов эвакуационных выходов) несут прямую угрозу конструктивной надежности и пожарной безопасности.

**«Инспектор ИИ»** автоматизирует труд государственного строительного инспектора, мгновенно находя расхождения и формируя юридически выверенные акты проверок и предписания с привязкой к нормативной базе (СП, ГОСТ, ПП РФ № 87, Градостроительный кодекс РФ).

## ✨ Ключевые возможности и функциональные модули

### 1. 📊 Мониторинг и Дашборд объектов (`Dashboard`)
- Централизованный обзор строящихся объектов Москвы с присвоением риск-статуса (**Зелёный**, **Жёлтый**, **Красный**).
- Сводная аналитика нарушений по категориям критичности (Критические, Значительные, Незначительные).
- Воронка обработки параметров: *Всего проверено -> Подтвержденные нарушения -> Кандидаты -> Норма подтверждена -> Требует пояснений*.

### 2. 🔍 Инспекционное рабочее пространство (`InspectionWorkspace`)
- **Двухоконный и трехоконный сравнительный просмотр** документов (ПД vs РД vs ИД).
- **Интерактивный Bounding Box / Overlay**: подсвечивание точных фрагментов чертежей и спецификаций с визуализацией расхождений.
- **Инструменты верификации инспектора**:
  - Принятие замечания (`Подтвердить нарушение`).
  - Отклонение с обязательным указанием нормативного кода причины:
    - `WRONG_REVISION` — Сравнение с неактуальной ревизией листа;
    - `APPROVED_CHANGE` — Согласованное изменение (лист согласования/разрешение на изменение);
    - `OCR_ERROR` — Ошибка оптического распознавания текста;
    - `ALIGNMENT_ERROR` — Ошибка совмещения слоев/осей;
    - `PARAMETER_NOT_APPLICABLE` — Параметр не применимым к данному конструктиву;
    - `EXCEED_TOLERANCE_ACCEPTABLE` — Отклонение в пределах допустимых допусков по СП;
    - `OTHER` — Иная обоснованная причина.

### 3. 📐 Парсинг штампов и чертежей (`DrawingParserTab`)
- Автоматическое распознавание основной надписи (штампа) по **ГОСТ Р 21.101-2020** (шифр объекта, раздел, стадия, номер листа, ревизия, фамилии разработчиков, ГИП).
- Определение масштаба, координатных осей и слоёв чертежей.
- Автоматическая классификация загружаемых документов (ПД, РД, ИД) на основе текстовых и графических признаков с точностью >98%.

### 4. 🧠 Генератор гипотез и коллизий (`HypothesisTab`)
- Интеллектуальный поиск скрытых коллизий методами:
  - **Логический анализ связей** (например, диаметр арматуры в КР vs спецификация);
  - **Семантический диссонанс** (расхождения в текстовых указаниях ПЗ и чертежах АР/КР);
  - **Нормативный аудит** (проверка на соответствие СП 63.13330, СП 16.13330, СП 1.13130, СП 118.13330);
  - **ML-паттерны** (предсказание типичных мест фальсификаций и ошибок генподрядчиков).
- Интерактивный конструктор гипотез для быстрого добавления инспектором новых проверочных шаблонов.

### 5. 📑 Реестр исполнительной документации (`ExecutiveDocumentationRegistry`)
- Электронный учет актов освидетельствования скрытых работ (АОСР) по РД-11-02-2006 / Приказу Минстроя № 344/пр.
- Контроль наличия геодезических исполнительных схем и паспортов/сертификатов на материалы (бетон, арматура, сэндвич-панели).
- Двусторонняя проверка: сверка объемов и дат в АОСР с общим журналом работ (РД-11-05-2007) и проектом.

### 6. 🏛 Интеграция с ИАС РИН Мосгосстройнадзора (`IaisRinTab`)
- Прямая синхронизация с **Информационно-аналитической системой управления контрольно-надзорной деятельностью (ИАС РИН)**.
- Формирование структурированных пакетов данных проверки (JSON/XML).
- Подписание актов проверки и предписаний **Усиленной квалифицированной электронной подписью (УКЭП)** инспектора по стандарту **ГОСТ Р 34.10-2012 / ГОСТ Р 34.11-2012**.

### 7. 🤖 ML-репозиторий и дообучение моделей (`MLRepositoryTab`, `MLRetrainingTab`)
- Управление версиями весов специализированных моделей (текущий рабочий чекпоинт `v2.4.2-altufievo-finetuned`).
- Формирование «Золотого датасета» (Gold Standard Ground Truth) на основе вердиктов экспертов-инспекторов.
- Пайплайн запуска дообучения (`fine_tune_pipeline.py`) с отслеживанием метрик в реальном времени.

### 8. 🛡 Неизменяемый журнал аудита WORM (`AuditLogTab`)
- Принцип **Write Once, Read Many (WORM)** для исключения фальсификации результатов проверок.
- Фиксация каждого действия (загрузка файла, подтверждение/отклонение замечания, подписание УКЭП, экспорт).
- Формирование криптографических хешей записей аудита для гарантии неизменности истории.

|--------------|-------------------------|-------------------|-----------------------------------|-------------------|
| **ПЗ** | Пояснительная записка | 8 | ТЭПы, площадь застройки, этажность, класс энергоэффективности | ПП РФ № 87, СП 118.13330 |
| **СПЗУ** | Схема планировочной организации земельного участка | 12 | Границы ГПЗУ, красные линии, процент застройки, проезды МЧС | СП 42.13330, СП 4.13130 |
| **АР** | Архитектурные решения | 24 | Высотные отметки, ширина коридоров и выходов, огнестойкость ограждений | СП 54.13330, СП 1.13130 |
| **КР** | Конструктивные решения | 28 | Класс бетона, диаметр/шаг рабочей арматуры, глубина заложения свай | СП 63.13330, СП 22.13330 |

## 🧠 ML-модели и пайплайн дообучения

В состав системы входит специализированная мультимодальная архитектура для анализа строительной документации:
- **Детекция и извлечение таблиц и штампов:** Выделение зон основных надписей по ГОСТ 21.101-2020.
- **Cross-Document Entity Linking:** Связывание позиций между ведомостями расхода стали, планами армирования и паспортами качества свай.
- **Модель детекции нарушений (`inspector_hypothesis_v2.4`):**
  - Обучена и валидирована на реальном комплекте документации г. Москвы (*Торговое здание, Алтуфьевское шоссе, вл. 79Б, стр. 1*).
  - **Character Accuracy (OCR):** 98.8%
  - **Exact Match (марки материалов):** 95.2%
  - **BBox IoU (точность локализации):** 97.2%
  - **Precision:** 98.2%
  - **Recall:** 94.5%
  - **Интегральный F1-score:** 96.8%

Запуск переобучения пайплайна:
```bash
python ml_models/inspector_hypothesis_v2.4/fine_tune_pipeline.py --epochs 5 --dataset dataset_altufievo_ground_truth.json
```

## 🔒 Интеграция с ИАС РИН и подписание УКЭП

1. **Формирование дела проверки:** Агрегация всех подтвержденных инспектором нарушений, доказательных фрагментов (BBox-полигонов) и ссылок на листы ПД/РД/ИД.
2. **Криптографическое подписание:**
   - Поддерживаются сертификаты квалифицированной электронной подписи по стандартам **ГОСТ Р 34.10-2012** (длина ключа 256/512 бит) и **ГОСТ Р 34.11-2012**.
   - Формирование отсоединенной или присоединенной подписи (форматы CMS/CAdES-BES).
3. **Шлюз взаимодействия с ИАС РИН:**
   - Передача пакета через защищенный REST/SOAP API с присвоением входящего номера и трекингом статуса проверки в режиме онлайн.

## 👥 Ролевая модель доступа (RBAC)

Система поддерживает 4 базовые роли с разграничением прав:
1. **Инспектор Мосгосстройнадзора (`INSPECTOR`):**
   - Загрузка проектной, рабочей и исполнительной документации.
   - Проведение проверок, верификация гипотез (подтверждение/отклонение нарушений).
   - Подписание предписаний личной УКЭП.
2. **Супервайзер / Начальник управления (`SUPERVISOR`):**
   - Контроль работы подведомственных инспекторов.
   - Утверждение предписаний высокой степени опасности.
   - Сквозной мониторинг строительных объектов Москвы.
3. **ML-инженер / Аналитик данных (`ML_ENGINEER`):**
   - Мониторинг метрик распознавания и детекции коллизий.
   - Формирование эталонных выборок и запуск дообучения моделей.
   - Управление репозиторием чекпоинтов.
4. **Администратор системы (`ADMIN`):**
   - Управление справочниками нормативной базы (СП, ГОСТ, приказы).
   - Настройка интеграций с ИАС РИН.
   - Контроль целостности WORM-журнала аудита.

## 🚀 Установка и запуск

### Системные требования
- **Node.js:** версия 18.0 или выше (рекомендуется 20 LTS)
- **Менеджер пакетов:** npm, pnpm или bun
- **Python (для ML-пайплайна дообучения):** 3.10+ с установленными `torch`, `transformers`

### Пошаговая инструкция

1. **Клонирование репозитория:**
   ```bash
   git clone <URL_РЕПОЗИТОРИЯ>
   cd inspector-ai-stroynadzor
   ```

2. **Установка зависимостей фронтенда:**
   ```bash
   npm install
   ```

3. **Запуск сервера разработки:**
   ```bash
   npm run dev
   ```
   Приложение откроется по адресу `http://localhost:3000`.

4. **Проверка типов и линтинг:**
   ```bash
   npm run lint
   ```

5. **Сборка для промышленного развертывания (Production build):**
   ```bash
   npm run build
   ```
   Собранное статическое приложение размещается в каталоге `dist/`.

6. **Предпросмотр production-сборки:**
   ```bash
   npm run preview
   ```

## 🛠 Сценарий работы инспектора (Quick Start)

1. **Создание объекта строительства:**
   - Нажмите кнопку **«+ Создать объект»** в верхнем меню.
   - Заполните наименование объекта, адрес, номер разрешения на строительство (РНС), реквизиты заказчика и подрядчика.
2. **Загрузка документации:**
   - Нажмите кнопку **«Загрузить ПД / РД / ИД»**.
   - Перетащите PDF-файлы проектной, рабочей или исполнительной документации.
   - Умный классификатор автоматически определит стадию документа, раздел по ПП РФ № 87 и реквизиты штампа ГОСТ.
3. **Верификация нарушений в «Рабочем месте инспектора»:**
   - Перейдите на вкладку **«Верификация протокола»**.
   - В левом списке выберите проверяемый параметр (например, *«КР-55. Класс бетона монолитных ростверков»*).
   - В центральной области просмотрите подсвеченные доказательные фрагменты (ПД vs РД vs ИД).
   - Примите решение:
     - Нажмите **«Подтвердить нарушение»** для включения в проект предписания;
     - Либо нажмите **«Отклонить замечание»** с выбором обоснования из выпадающего списка (например, *«Согласованное изменение»*).
4. **Формирование и подписание предписания:**
   - Перейдите на вкладку **«Интеграция ИАС РИН»**.
   - Ознакомьтесь с автоматически сформированным проектом Предписания об устранении нарушений.
   - Вставьте ключевой носитель (Рутокен/JaCarta) и нажмите **«Подписать УКЭП инспектора»**.
   - Нажмите **«Синхронизировать с ИАС РИН»** — делу проверки будет присвоен уникальный входящий номер в государственной системе.
5. **Экспорт отчетности:**
   - Нажмите **«Экспорт»** на панели инструментов для скачивания официального акта проверки в формате PDF, реестра несоответствий в Excel или машиночитаемого пакета XML/JSON.
